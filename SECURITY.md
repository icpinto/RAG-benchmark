# Security Policy

## Supported versions

This project is in early development. Security fixes are provided for the current `main` branch and the latest tagged release, when tags are available.

| Version | Supported |
| --- | --- |
| Current `main` branch | Yes |
| Latest tagged release | Yes |
| Older commits or releases | No |

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Report security concerns privately by emailing security@example.com with:

- A description of the issue and affected component.
- Steps to reproduce or proof-of-concept details.
- Potential impact and any known mitigations.
- Your preferred contact information for follow-up.

We aim to acknowledge reports within 5 business days and will coordinate remediation and disclosure with the reporter when practical.

## Handling sensitive data

Do not include secrets, proprietary documents, production datasets, API keys, tokens, or credentials in issues, pull requests, logs, screenshots, benchmark artifacts, or sample configuration files. Use redacted examples or synthetic data instead.
